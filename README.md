## PrimeVue를 토큰에 묶는 법

**색을 프리셋에 적지 않는다.** `src/ws/preset.ts`의 색은 전부 `var(--ws-*)`다. 라이트·다크 두 벌이
같은 매핑을 가리키고, 값을 바꾸는 건 `tokens.css`의 `[data-theme='dark']` 블록 하나다.
그래서 대비 검사도 `tokens.css` 한 곳만 보면 된다.

```js
// main.ts
theme: {
  preset: WsPreset,
  options: { darkModeSelector: '[data-theme="dark"]', cssLayer: { name: 'primevue', order: 'reset, primevue' } },
}
```

**레이어 순서가 규칙이다.** `reset < primevue < 레이어 밖(우리 보정)`.

- 전역 리셋(`button { color: inherit }` 등)은 `@layer reset`에 둔다. 레이어 밖에 두면 PrimeVue를 이긴다 —
  실제로 조회 버튼 글자가 본문색을 물려받아 3.44로 떨어졌다.
- 우리 보정(`primevue.css`)은 레이어 밖이라 특정성과 무관하게 PrimeVue를 이긴다.

**높이 32는 두 곳이 같이 맞춘다.** 높이 = 테두리 2 + 안쪽 위아래 + 줄 높이.

| | 안쪽 위아래 (프리셋) | 줄 높이 (CSS) | 합 |
|---|---|---|---|
| 입력 · 선택 · 버튼 | 5 + 5 | 20 | 32 |
| 세그먼트(SelectButton) | 5 + 5 | 20 | 32 |
| 작은 버튼 | 1 + 1 | 20 | 24 |
| 로그인 | 9 + 9 | 20 | 40 |

Aura는 입력 글자 크기를 토큰이 아니라 CSS에 `1rem`으로 박는다. 그래서 글자 14 · 줄 높이 20은
`primevue.css`가 맡는다. Aura 기본값 그대로면 같은 크기끼리도 입력 38 · 선택 42 · 버튼 39로 흩어진다.

**버튼 뜻** — 원본 규칙을 severity로 옮겼다.

| 원본 | 자리 | PrimeVue |
|---|---|---|
| `.shbox .btn_cm.pri` 초록 | 조회 · 팝업 확인 | `severity` 없음 (primary) |
| `.btn_cm.pri` 진회색 | 저장 · 등록 | `severity="contrast"` |
| `.btn_cm.sec` 회색 | 보조 | `severity="secondary"` |
| `.btn_cm` 흰색 | 기본 | `severity="secondary" outlined` |
| — | 위험 | `severity="danger" outlined` |
| 윤곽 알약 | 그리드 제목줄 보조(CSV·행추가) | `severity="secondary" outlined class="ws-line"` |

세그먼트는 고른 칸을 저장 버튼 색으로 채운다. Aura 기본은 회색 판 위 흰 칸이라 고른 칸과 판이 1.1:1이다.

## 다크

원본에 다크가 없어서 새로 짠 층이다. 규칙 셋.

1. **색 계열은 라이트와 같다.** 초록은 초록, 링크는 파랑이다. 명도만 옮긴다
2. **면은 세 단계로만 쌓는다.** 캔버스 `#14181b` < 면 `#1b2024` < 머리 `#252c31`. 그림자 대신 명도로 층을 가르고, 카드는 그림자를 끄고 선 `#2b3237`을 준다
3. **값은 빌드에서 잰다.** `check:contrast`가 라이트와 같은 쌍을 다크에서도 잰다 — 110쌍, 미달 0

뒤집히는 건 저장 버튼 하나다(진회색 `#444` → 밝은 회색 `#d6dce0` + 검은 글자). 어두운 바탕에 어두운 버튼은 안 보인다.
사이드 알림 숫자는 전용 토큰 `--ws-count-bg`를 쓴다. 위험 글자색에 흰 글자를 얹으면 다크에서 2.48이다.

Tabulator 기본 스킨(`tabulator_simple`)은 행 글자 `#333` · 범위 강조 `#d6d6d6`을 박아 둔다. 다크에서 행이 안 보여서
`tabulator-ws.css` 끝에서 더 높은 특정성으로 토큰에 다시 묶었다.

## 셸 — 전폭 상단바 + 메뉴 사이드바 (D6 A)

```
┌──────────────────────────────────────────────────────────────┐
│ ☰ 로고 시스템명▾   [ 통합 검색  / ]      전역 조건 ▾  ☾  🔔 79  (김) │ 상단바 48
├──────────┬───────────────────────────────────────────────────┤
│ 메뉴     │ 탭줄 (180px 고정 폭)                                │
│   ⋮      │                                                   │
│          │ 화면 (KeepAlive 8장)                               │
│ 대응표   │                                                   │
│ 새 요소  │                                                   │
└──────────┴───────────────────────────────────────────────────┘
```

- **위는 어디서든 같은 것, 왼쪽은 어디로 가나.** 사이드바에 검색 · 알림 · 사용자가 섞여 있으면 메뉴가 짧아지고, 전역 조건이 탭줄 끝에 따로 떨어졌다
- **통합 검색** — `/` 또는 ⌘K. 메뉴는 트리에서 바로, 업무 데이터(기업 · 접수번호 · 회원 · 적발 번호)는 처음 검색할 때 늦게 싣는다. 회원은 2자 이상이고 이름을 가려 보인다. 고른 회원 이름은 **주소에 싣지 않고** 메모리로 넘긴다
- **테마 버튼**을 상단바에 따로 둔다 — 사용자 메뉴 안에만 있을 때 다크 전환을 찾지 못했다. "시스템 따르기"는 사용자 메뉴에 남긴다
- **알림**은 메뉴의 처리 대기 건수를 모은다(목업). 누르면 그 화면으로 간다
- **상단바 색** `--ws-top-bg #1f2d2b` — 사이드바(#2a403d)보다 한 단 짙게 해 ㄱ자 틀 안에서 둘을 가른다. 글자 11.95 · 보조 6.89 · 검색칸 테두리 4.5
- **접기(레일 64px)** 는 상단바 ☰. 상태는 `ds3-rail`. 레일에서 그룹 아이콘에 올리면 옆으로 하위 메뉴가 뜬다
- 레일에서는 메뉴 영역의 스크롤을 푼다. `overflow-y: auto`면 x도 `auto`로 계산돼 옆으로 뜨는 메뉴가 잘린다
- 1024 폭까지 한 줄에 든다 — 검색칸이 `min(440px, 36vw)`로 줄어든다
- **스크롤바**는 토큰으로 칠한다 — 트랙 투명 · 손잡이만(바탕과 3:1). 사이드바는 레일 색 위 전용 손잡이

### 새 화면 만드는 순서

1. 루트는 `.ws-page`, 첫 자식은 `<PageHead />`. 대시보드·통계면 `.ws-page--canvas`를 더하고 구획에 `.ws-card`
2. 목록이면 `<WsSearch>`에 `<tr>`만 넘긴다 — 라벨·칸 세 쌍이 한 줄
3. 구획은 `.ws-sec` = `.ws-tit`(왼쪽 제목·건수 / 오른쪽 버튼) + 내용. 제목줄 → 내용 12px
4. 컨트롤은 PrimeVue를 그대로 쓴다. 크기 prop을 주지 않으면 32다
5. 조회는 primary, 저장은 contrast — 위 버튼 표
6. 목록은 `<QueryState>`로 감싼다 — 로딩 · 오류 · 빈 · 정상
7. 입력 표는 `.ws-tb`, 필수는 `th.req`

### 그리드 규칙 (`TabGrid`)

| 자리 | 규칙 |
|---|---|
| 높이 | 머리 · 행 35. 2단 머리글이면 머리 70 |
| 체크박스 열 | 머리 · 행 모두 **가로 · 세로 가운데**. 머리 체크박스 = 지금 조회 결과 전체 선택 |
| 2단 머리글 | 묶음이 아닌 열(체크박스 · 번호 · 기업명)은 머리 높이 전체의 세로 가운데 — rowspan처럼 |
| 제목 | 가운데. 숫자 열은 값만 오른쪽, 제목은 가운데 |
| 복합 값 | 한 칸 줄바꿈 금지 — 2단 머리글 열로 나눈다(행 35 유지, 칸마다 정렬) |
| 칸 안 동작 | 버튼 `.ws-cellbtn`(24) · 링크 `.ws-celllink`. 누르면 제 일만 한다 — 행 열기(패널)와 겹치지 않는다 |
| 선택 | 쪽을 넘기거나 다시 조회하면 풀린다 — 보이지 않는 행이 일괄 처리에 섞이지 않게 |
| 열이 많으면 | 기본 열만 두고 묶음(계좌 · 첨부 …)을 켜고 끈다. 1440 폭에서 가로 스크롤이 없어야 한다 |

머리 체크박스가 왼쪽으로 10px 치우쳤던 적이 있다 — 스킨이 머리 칸을 flex로 만들면서 제목칸이 내용 폭으로 줄어
가운데 정렬이 먹지 않았다. `.tabulator-col-title-holder { flex: 1 }`로 고쳤다(`tabulator-ws.css`).

## 실측

관리자 센터 9화면 + 로그인 × 라이트·다크 전수(2026-09-28 폐기 전 기록).

| | 결과 |
|---|---|
| 블록 간격 | `[18, 24]` — 제목 영역 아래 18, 나머지 24 |
| 컨트롤 높이 | 32 (로그인 40) — 입력 · 선택 · 다중선택 · 숫자 · 날짜 · 자동완성 · 버튼 · 세그먼트 |
| 그리드 행 | 35 |
| 그려진 글자 대비 | 미달 0 — 화면당 33~439개 글자 요소, 로고 제외 |
| 콘솔 오류 · 경고 | 0 |

대비는 토큰 쌍(`check:contrast`)과 화면에 그려진 색(실측) 두 번 잰다. 토큰 쌍만 보면
Aura 기본값이 새는 자리를 못 잡는다 — 세그먼트가 슬레이트 회색 4.34로 남아 있던 것을 실측이 잡았다.

**실측 함정.** 숨은 브라우저 창에서는 CSS 전환이 멈춰, 윤곽 버튼이 전환 첫 프레임 색(1.40)으로 읽힌다.
재기 전에 `transition: none`을 주입한다.

### 옮기면서 잡은 것

- **이중 축 차트가 죽어 있었다.** `EzChart`가 `yAxis`를 객체로 펼쳐, 배열(이중 축)이 `{0:…, 1:…}`이 됐다.
  setOption이 "yAxis 0 not found"로 중간에 죽고, 그 뒤로 인스턴스가 "main process" 오류를 계속 낸다. **DS1·DS2에도 같은 코드가 있다**
- **체크박스 누름 영역이 16px이었다.** DS2의 `.ws-check input { width: 16px }`이 PrimeVue 체크박스의 투명 입력에 걸려
  20px 상자 안에서 16px만 눌렸다. 네이티브 클래스를 지우면서 풀렸다
- **Tabulator 경고 둘.** 우리 키 `paste`를 컬럼 정의에 둔 채 넘겨 "Invalid column definition" — `TabGrid`가 넘기기 전에 뺀다.
  주문 그리드의 `frozen`은 범위 선택과 섞이면 동작이 보장되지 않아 뺐다

## 지원 사업 관리 미리보기 — `#/sp`

처음에는 셸 하나가 관리자센터(샘플)와 지원 사업 관리를 같이 싣고 브랜드로 오갔다. 2026-09-28 관리자 센터를 없애며
대시보드는 `업무 현황`, 통계는 통계·리포트의 `사용현황`, 공통코드는 `시스템 관리`로 옮겨 **지원 사업 데이터로 다시 채웠다**.
컴포넌트 카탈로그는 사이드바 바닥(`#/sp/catalog`)으로. 첫 화면(고정 탭)은 업무 현황이다.

근거는 기존 관리자시스템 한 곳의 AS-IS 분석(비공개)이다. 공개 저장소라 **사업명 · 기관명 · 코드값 · 실측 수치를 일반화하거나
지어낸 값으로 바꿨다** — 화면 구조와 업무 패턴만 남긴다.
목적은 둘 — **분석된 화면을 DS3에 얹으면 무엇이 더 필요한가**, **IA가 확정되면 어떻게 그려질까**.
데이터는 전부 지어낸 값이다(분석 자료에는 행 데이터가 없다). **메뉴는 제안이고 확정이 아니다.**

### 제안 메뉴 — AS-IS 54 → 48

조직 기준(업무게시판 · 회원관리 17개 · 임직원정산 …)을 **업무 흐름** 기준으로 다시 묶었다 —
참여 심사 → 기업·기관 → 근로자·포인트 → 자금·정산 → 부정행위·제재 → 통계 → 사업 설정 → 대외 컨텐츠 → 업무 협업 → 시스템 관리.
AS-IS 14화면을 7자리로 합쳤다(RPA 사본 3쌍 · 중복 등록 2쌍 · 계정 2 · 청구서 결과 핸들러). 비밀번호 변경은 사용자 메뉴로 뺐고,
메뉴 밖에 있던 메인 대시보드를 `업무 현황`으로, AS-IS에 없던 `공통코드`를 시스템 관리에 넣었다. 두 방향 대응표는 `메뉴 대응표`(`#/sp`)에 있다.

### 새 화면 요소 — 35건 (전부 구현)

`새 화면 요소`(`#/sp/elements`)가 정본이다. 요소마다 AS-IS 근거와 "필요한 AS-IS 화면 수"를 단다 —
분석 시트 속성(유형 · 외부연동 · 개인정보)으로 고른 **추정치**다. 큰 것만:

- **전역 조건 선택기** — 참여년도 × 사업을 상단바에 한 번. AS-IS는 20개 넘는 화면의 조회 첫 줄에 반복했다
- **처리 확인 팝업** — 대상 건수 + 사유 · 날짜 + "LMS · E-Mail이 나간다"를 버튼 바로 위에. AS-IS 모달 21개 대부분이 이 틀 하나로 된다(세션 만료 · 참여불가 경고는 따로)
- **결과 보고** — 처리 완료 · 처리 실패 · 통지 실패(상태는 바뀜)를 따로 센다
- **엑셀 세 관문** — 상한을 버튼 옆에 미리, 재인증, 반출 사유(직접 입력 10~200자)
- **개인정보 가림** — 목록은 늘 가리고 상세에서 열면 기록. AS-IS는 반출은 통제하면서 조회는 평문이었다
- **서버 페이징 · 2단 머리글 집계표 · 기간 입력(타자 가능 · 범위 제한 즉시)** — 거의 전 목록
- **상태별 허용 처리 · 일괄 적격 미리보기** — 행마다 다른 버튼 대신 규칙표 한 곳(`src/sp/company.ts`). 일괄 버튼이 "할 수 있는 곳 / 선택"을 싣는다

식별만 해 두었던 셋도 그렸다 — 세션 만료 알림(사용자 메뉴 › 세션 만료 알림 보기) · 엑셀 업로드 행별 오류(참여 기업 등록) · 탭 넘침(국회요구자료).

**상태 · 처리 규칙은 [`docs/state-rules.md`](docs/state-rules.md)** — 백엔드 · 기획과 맞출 합의용 초안. 코드 정본은 `src/sp/company.ts` · `src/sp/member.ts`.

### 그리면서 잡은 것 — DS3 공용 부분

- **쪽을 넘겨도 선택이 남아 있었다.** 조회 중 `QueryState`가 그리드를 내리는데, 내려가는 그리드가 "선택 0"을 알리지 않아
  화면의 "선택 N건"과 일괄 버튼이 없는 선택을 붙들었다. `TabGrid`가 데이터 교체 · 내려감에서 선택을 푼다 — 샘플 화면도 같이 고쳐졌다
- **위험 확정 버튼(solid danger)이 3.76** — Aura 기본 빨강이었다. `--ws-action-danger` 토큰을 두 테마에 두고 대비 검사 쌍에 넣었다(114쌍)
- **옆 글자가 길면 버튼이 두 줄**(52px) — `.p-button { white-space: nowrap }`
- **첫 로드가 94KB로 뛰었다** — 셸이 전역 조건 선택기(Select · Popover)를 정적으로 물었다. 비동기로 바꿔 67KB
- **칸 안 버튼을 누르면 행 패널도 같이 열렸다** — `TabGrid`의 행 클릭이 칸 버튼 · 링크를 거른다
- **일괄 결과가 실행 전에 뺀 곳을 "처리 실패"로 셌다** — 결과 팝업이 "실행 전에 뺀 곳"을 따로 적는다(`skipped`)
- **차트 범례 · 툴팁이 다크에서 기본색이었다** — `EzChart`가 병합한 legend · tooltip · grid 위에 화면 옵션 원본을 다시 펴서
  글자색 · 배경이 ECharts 기본값으로 돌아갔다. 원본을 먼저 편다. 범례 기본 자리도 위로 박았다(아래로 새서 x축 글자와 겹쳤다)
- **통계 화면에서 상단바가 밀려 올라갔다** — 표 caption의 `.ws-sr-only`(absolute)가 본문 스크롤 영역 밖을 기준으로 잡혀
  문서 높이를 900 → 1419로 늘렸다. 본문 스크롤이 끝나면 바깥 문서가 이어 밀렸다. `.sh-scroll`에 `position: relative`
- **상단바 전역 조건 칩에 보정이 안 걸렸다** — `SpContext`가 두 뿌리(칩 + 팝오버)라 `class`가 붙지 않아 `:deep` 보정이 빗나갔다. 감쌌다

### 실측 — 지원 사업 19경로

블록 간격 `[18, 24]` · 컨트롤 32 · 그리드 행 35(2단 머리글 70) · 가로 넘침 0 · 대비 미달 0(두 테마, 팝업 · 옆 패널 포함) · 콘솔 0.

2026-09-28 글꼴 교체 · 흡수 뒤 23경로(목록 20 · 상세 3) × 두 테마를 다시 쟀다 — 컨트롤 32(로그인 40) · 행 35 · 가로 넘침 0 ·
그려진 글자 대비 미달 0(화면당 119~484개) · 문서 높이 = 화면 높이 · 콘솔 경고 0. 블록 간격은 다시 재지 않았다.
상호작용: 상태 변경 · 집계 드릴 · 선정 처리 결과 · 다운로드 세 관문 · 참여불가 경고 → 승인 · 상세 저장 · 가림 열람 ·
일괄 취소 네 단계와 역할 전환 · 사이트 × 조치 드릴 · 고객사 찾기 · 단위 전환 · 배너 업로드 제약 넷 ·
