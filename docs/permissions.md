# 계정 역할과 권한 체계

지원 사업 관리 어드민(TO-BE)의 계정 · 역할 · 동작 권한 기준이다. 코드 정본은 `src/sb/roles.ts`
(`ROLES` · `ACTIONS` · `DEFAULT_MATRIX`)이고, 이 문서는 그 근거와 규칙을 적는다.
화면 명세는 이 문서의 역할 코드와 동작 코드로 화면별 역할 × 동작 표를 채운다.

## 0. 먼저 알아 둘 것 — 근거의 한계

- **AS-IS 조사 계정은 1개다.** 지원기관 역할권한 4등급 중 **최하위 등급**(담당자) 계정으로 **조회만** 했다.
  저장 · 승인 · 발송 · 포인트 배정 같은 쓰기 조작은 한 번도 실행하지 않았다.
- 그래서 **상위 3개 등급(지원담당 · 지원총괄 · 사업총괄)이 무엇을 더 보고 무엇을 더 할 수 있는지는 미확인**이다
  (AS-IS 미결 Q-13). 기업담당자 등급은 매뉴얼로 메뉴 4개만 본다는 것만 안다.
- TO-BE IA 상세 시트의 `권한(확인필요)` 열은 **모든 행이 비어 있다.** 권한 정책 문장은 로그인 · 신청 · 담당자 ·
  업무요청 · 공지 행에만 있다.
- 따라서 `DEFAULT_MATRIX`의 값은 대부분 **추정**이다. 화면 명세는 각 칸의 확인 수준을 이 문서 기준으로 적고,
  추정 칸을 확인으로 바꾸려면 9절 미결 질문의 답이 필요하다.

### 확인 수준

| 수준 | 뜻 | 이 문서에서의 예 |
|---|---|---|
| `확인` | AS-IS 실측 또는 IA 문장에 근거 | 마스터/일반 구분, 일반 계정은 타 계정 관리 불가, 버튼 단위 권한 문구 존재 |
| `추정` | 업무 성격에서 끌어낸 합리적 가정 | 역할별 동작 배정 대부분, 역할과 AS-IS 등급의 대응 |
| `미확인` | 근거가 없고 가정도 어렵다 | 상위 등급의 실제 메뉴, 포인트 수동 지급 화면의 존재 |

## 2. 역할 정의

역할 이름에 "관리자"를 쓰지 않는다(위 RFP 요구). IA 메뉴명 `관리자로그인` · `관리자관리` · `관리자 접속이력`은
화면에 노출되면 같은 요구에 걸린다 — 명칭 정리는 9절 Q-P12.

| 코드 | 역할 | 조직 | 등급 | 하는 일 | AS-IS 대응 | 수준 |
|---|---|---|---|---|---|---|
| `AM` | 지원기관 마스터 | 지원기관 | 마스터 | 지원기관 계정 발급 · 회수 · 권한 부여, 사업 설정, 일괄 참여취소 같은 비가역 처리, 이력 점검 | 사업총괄 | 추정 |
| `AL` | 지원기관 총괄 | 지원기관 | 총괄 | 선정 · 승인 확정, 금전 처리, 일괄 처리, 콘텐츠 게시 | 지원총괄 | 추정 |
| `AS` | 지원기관 담당자 | 지원기관 | 담당 | 신청 · 참여 · 노동자 심사 실무. 건별 상태 변경 · 발송 · 개인정보 다운로드(사유) | 지원담당 · 담당자 | 추정 |
| `AV` | 지원기관 조회 전용 | 지원기관 | 조회 | 조회와 개인정보 없는 다운로드. 개인정보는 마스킹 | 없음 | 추정 |
| `OM` | 운영사 마스터 | 운영사 | 마스터 | 운영사 계정 발급 · 회수 · 권한 부여, 이력 점검, 전용몰 · 콘텐츠 운영 | 없음(AS-IS는 기존 운영사가 직접 운영) | 추정 |
| `OO` | 운영사 운영자 | 운영사 | 담당 | 업무요청 · 문의 답변, 전자청구서 작성, 부적합 상품 조치, 기업담당자 잠금 해제(CS) | 없음 | 추정 |
| `CM` | 기업 담당자 | 기업 | 연계 | 기업 어드민 계정. **이 어드민에는 접근하지 않는다.** 연계 화면의 상대편 기준으로만 둔다 | 기업담당자 | 확인(별도 시스템) |

- AS-IS 4등급을 TO-BE 4역할(AM · AL · AS · AV)에 그대로 옮기지 않았다. AS-IS 담당자 등급(조사 계정)은
  메뉴 10개를 보고 쓰기 버튼도 보였으므로 조회 전용이 아니다 → `AS`로 묶었다. `AV`는 감사 · 보고용 신설이다.
- 마스터는 조직마다 따로다. `AM`은 지원기관 계정만, `OM`은 운영사 계정만 관리한다(추정 — IA 문장
  "마스터 계정 관리는 지원기관 또는 운영사만"의 해석. 9절 Q-P2).

## 3. 계정당 권한 — 역할 기본값 + 계정별 조정

이번 작업의 핵심이다. **권한은 역할이 아니라 계정에 붙는다.** 역할은 기본값일 뿐이다.

```
계정 = 조직 + 역할 1개 + 사업 범위 + 개별 조정 목록
허용 = (역할 기본값 ∪ 개별 추가) − 개별 회수, 단 사업 범위 밖 데이터는 조회도 불가
```

| 규칙 | 내용 | 수준 |
|---|---|---|
| 역할 1개 | 계정은 역할을 하나만 가진다. 두 역할이 필요하면 계정을 나눈다 | 추정 |
| 사업 범위 | 계정마다 볼 수 있는 사업(`BIZ-26-01`~`04`)을 고른다. 기본은 전체. 26년 지역 연계 지원사업 담당처럼 한 사업만 보는 계정을 만들 수 있다 | 추정 |
| 개별 조정 단위 | 화면 코드 × 동작 코드. 추가 · 회수 모두 사유 입력, 조정한 사람 · 일시 기록 | 추정 |
| 개별 추가 상한 | `account`와 `money`는 **역할로만** 받는다(개별 추가 불가). `approve` · `bulk`는 `AL` 이상 역할 계정에만 추가 가능. `AV`에는 `download-pii`를 추가하지 못한다 | 추정 |
| 자기 권한 변경 금지 | 누구도 자기 계정의 역할 · 조정을 바꾸지 못한다. 마스터 권한 변경은 같은 조직의 다른 마스터가 한다 | 추정 |
| 마스터 최소 2명 | 조직마다 마스터가 2명 이상이어야 한 명을 사용중지할 수 있다 | 추정 |
| 표시 | 권한이 없는 동작 버튼은 숨기지 않고 비활성 + 안내("이 계정에는 ○○ 권한이 없습니다")로 보인다. 메뉴 자체 권한이 없으면 메뉴를 숨긴다 | 추정 (AS-IS 문구 방식 계승) |

## 4. 동작 정의

| 코드 | 이름 | 뜻 |
|---|---|---|
| `view` | 조회 | 화면 진입과 목록 · 상세 조회. 개인정보는 마스킹 기본 |
| `create` | 등록 | 새 건 등록 — 게시물, 답변, 메모, 첨부, 발급 |
| `update` | 수정 | 기존 건 수정. 업무 데이터 수정은 수정 사유 필수 |
| `delete` | 삭제 | 콘텐츠 삭제 · 매핑 해제 한정. 계정 · 신청 · 이력은 삭제하지 않는다 |
| `approve` | 승인 · 확정 | 최종 상태로 보내는 결재성 결정 — 선정완료, 반려, 인원추가 승인, 청구 승인 |
| `status` | 상태 변경 | 상태 변경 모달 처리 — 정상접수, 보완요청, 이용정지, 참여불가 적용/해제, 문의 처리상태 |
| `bulk` | 일괄 처리 | 여러 건 한 번에. **일괄 버튼 = 해당 동작 + `bulk`** (일괄 이용정지 = `status`+`bulk`, 일괄 환불요청 = `money`+`bulk`) |
| `download` | 다운로드 | 개인정보 없는 엑셀 · 파일(집계 통계, 청구서 공문, 참여증서) |
| `download-pii` | 개인정보 다운로드 | 개인정보 포함 엑셀 · 서류. 사유 입력(`SP-CMN-040D`) + 개인정보 접근이력 |
| `send` | 발송 | LMS · E-Mail 수동 발송, 회신 메일. 상태 변경에 딸린 자동 통지는 `status`에 포함 |
| `money` | 금전 처리 | 입금 확인, 환불 요청 · 처리, 청구 승인, 환불계좌 확정 |
| `account` | 계정 관리 | 계정 생성 · 사용중지 · 잠금 해제 · 비밀번호 초기화 · 권한 부여 |
| `config` | 설정 | 사업 · 발전모델 · 인원 창구 · 코드 · 콘텐츠 게시(전시) 설정 |

## 5. 역할별 원칙 — 무엇을 떼어 놓나

| 원칙 | 규칙 | 수준 |
|---|---|---|
| 금전 분리 | `money`는 `AL` · `AM`만. 청구서는 **운영사가 작성(`OO` · `OM`), 지원기관 총괄 이상이 승인** — 작성 조직과 승인 조직이 다르다 | 추정 |
| 확정 분리 | 담당(`AS`)은 정상접수 · 보완요청 같은 중간 상태까지. 선정완료 · 반려 · 인원추가 승인은 `approve`(`AL` 이상) | 추정 (IA "심사 권한 보유자만 상태 변경") |
| 일괄 분리 | `bulk`는 `AL` 이상. 비가역 대량 처리(일괄 참여취소)는 `AM`만 | 추정 (기존 미리보기 가정 계승) |
| 개인정보 다운로드 분리 | `download-pii`는 `download`와 다른 권한. `AV`는 갖지 않는다. 매번 사유 + 접근이력 | 확인(사유) · 추정(배정) |
| 계정 분리 | 관리 화면(`SP-SYS-010*`)의 `account`는 `AM` · `OM`만. 기업담당자 계정의 잠금 해제 · 비밀번호 초기화는 `AL` 이상 + 운영사(CS) | 확인(마스터 전용) · 추정(기업담당자) |
| 설정 분리 | 사업 · 발전모델 · 인원 창구 `config`는 `AL` · `AM`. 콘텐츠는 작성(`AS` · `OO`)과 게시(`AL` · `AM` · `OM`)를 나눈다 | 추정 (IA 메모 "매뉴얼은 지원기관 승인 후 게시") |
| 조직 분리 | 운영사는 참여 심사 · 선정 · 금전 확정을 하지 않는다. 지원기관은 전용몰 상품 조치를 하지 않는다(조회만) | 추정 |
| 삭제 최소 | 계정 · 신청 · 처리이력 · 메모는 삭제 없음. `delete`는 콘텐츠 · 매핑 · 첨부 한정 | 확인(IA 여러 행) |

### 기업 담당자(`CM`)와 연계되는 화면

IA의 지원기관 전용 열이 `N`(기업도 필요)인 화면과, 기업 어드민에서 같은 데이터를 다루는 화면이다.
`CM`은 이 어드민에서 권한이 없지만, 아래 화면의 명세는 **기업 어드민 쪽에서 무엇이 먼저 일어나는지**를 적는다.

| 이 어드민 화면 | 기업 어드민에서 `CM`이 하는 일 | 수준 |
|---|---|---|
| `SP-OPS-010*` 업무요청 | 요청 등록 · 추가 요청(최대 5사이클). 지원기관 · 운영사가 답변 · 상태 변경 | 확인 |
| `SP-OPS-040*` 공지 | 기업공지 · 공통공지를 본다 | 확인 |
| `SP-PNT-*`, `SP-STL-040*` 포인트 · 이용 · 환불 | 자기 기업 소속 노동자분만 조회 | 확인(지원기관 전용 N) · 추정(범위) |
| `SP-PRT-030D` 노동자 상태관리 | 이용정지 처리 — IA는 `CM`만 처리한다고 쓴다 | 확인(IA) · 경계 B1 |
| `SP-PRT-040*` 기업담당자 | 자기 기업 담당자 추가 · 잠금 해제 · 비밀번호 초기화 | 확인(기업 IA) |
| `SP-BIZ-040*` 동반성장 | 참여기관(대기업) 담당자가 연계된 지원기업과 소속 노동자를 조회 | 확인(IA 메모) · 미확인(화면 위치) |

## 8. 경계 사례 — 명세에서 판단이 필요한 곳

| # | 사례 | 기본값 | 왜 경계인가 |
|---|---|---|---|
| B1 | 노동자 이용정지 | `AS` 이상 `status`, 일괄은 `AL` 이상 | IA는 "기업담당자만, 지원기관은 조회". AS-IS는 지원기관 화면에 이용정지 모달이 있다. IA가 확정되면 지원기관은 `view`로 내린다 |
| B2 | 신청 목록의 상태 변경 | 목록에서 `status` · `bulk`(선정 일괄) 허용 | IA 같은 행에 "목록에서 자격심사 상태 변경 가능"과 "목록에서는 승인 · 반려 · 보완요청 불가"가 함께 있다. 기본값: 목록은 중간 상태 · 선정 일괄만, 반려 · 보완요청은 상세 |
| B3 | 기업담당자 계정 조작 | `AL` · `AM` · `OO` · `OM`의 `account` | 관리 화면의 `account`는 마스터 전용인데, 기업담당자 잠금 해제는 CS 빈도가 높다. 기업 어드민에서도 할 수 있다 |
| B4 | 전자청구서 승인 | 운영사 작성, 지원기관 `AL` 이상 승인 · 금전 | 청구 → 승인 → 에스크로 출금 흐름에서 승인 주체가 IA에 없다 |
| B5 | 업무요청 상태 변경 주체 | 지원기관 · 운영사 둘 다 | IA 같은 행에 "요청상태는 지원기관 담당자 수정 불가"와 "지원기관 담당자만 변경 가능"이 함께 있다 |
| B6 | 다운로드 사유 대상 | `download-pii`에만 사유 | AS-IS는 **모든** 엑셀에 사유를 받는다. 통계 집계 다운로드도 받을지 정해야 한다. 재인증 팝업 유지도 미정 |
| B7 | 마스킹 해제 조회 | `view` 권한자 중 `AV` 제외, 해제 시 접근이력 | 동작 목록에 "마스킹 해제"가 따로 없다. 필요하면 동작을 추가한다 |
| B8 | 참여기업 일괄 등록 | `AL` · `AM` | AS-IS는 지원기관이 엑셀로 등록한다(상태 21종 지정). 상태를 임의로 지정하는 기능이라 사실상 상태 변경 + 일괄이다 |
| B9 | 포인트 수동 지급 · 회수 | 부여하지 않음 | 포인트 배정이 사업의 핵심 조작인데 AS-IS 조사 계정에서 화면이 안 보였다. TO-BE IA도 조회 화면뿐이다 |
| B10 | 운영사의 개인정보 다운로드 | 노동자 · 포인트 · 이용 · 환불 · 가상계좌 목록에서 허용 | CS · 정산 대사에 필요하다고 봤다. 지원기관이 운영사의 개인정보 반출을 허용할지 정해야 한다 |
